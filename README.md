# 江浙沪-音乐剧·话剧-速览

一个**个人向**的公开信息聚合页面：定时抓取江浙沪 22 个城市在演/待演的音乐剧、
话剧、博物馆特展/临展和商业展览，汇成手机端友好的静态页，可订阅日历。
页面地址：<https://zhaozixi.github.io/playlist/>

四个栏目：音乐剧 / 话剧 / 博物馆 / 展览。所有购票、预约入口一律跳转源站。

## 目录结构

```

crawler/museum.py             博物馆官网展讯 + 国家文物局「看展览」补录

crawler/probe_sources.py      开发调试用：大麦接口探针（区分协议错误与 IP 风控），不参与正式抓取
crawler/scheduler.py          早期无常驻 cron 环境的备选调度器，现由 GitHub Actions 替代
```

## 调度与高可用

排程目标是北京时间 **08:00 / 16:00** 各出一版数据，但 GitHub Actions 的
`schedule` 只是「尽力而为」——实测会延迟数小时甚至整槽跳过（2026-10-02、10-03
连续两天，CST 08:00 后的多个整点槽一条都没送达）。所以做了三层保障：

1. **内置排程加密盯梢**：cron `0 0-8,10-22/2 * * *`（UTC）＝北京时间
   08:00–16:00 每小时醒一次、其余时段每两小时一次。
2. **站外心跳**：一个 Cloudflare Worker 每小时 :45 调用
   `workflow_dispatch`（`external=true`）。心跳与内置 tick 走同一闸门，
   专门兜住 GitHub 调度器整体打盹的情况。
3. **闸门判重**：每一轮定时/心跳先跑 `crawler/gate.py`——08:00/16:00
   正点直接抓；其它时刻若该槽数据已新鲜则十几秒内退出，只有确认漏跑才补抓。
   因此多几路触发不会重复抓取、不会重复部署。

手动 `push`（限 crawler/**、web/build.py、workflows 自身）、UI 上直接
Run workflow、或带 `force=true` 的 dispatch，都会跳过闸门立即全量抓一轮。

失败分级：票务主源失败会把整站标 `stale`（页面红条）；博物馆/展览属于附加栏目，
失败只在顶部挂一行提示，且仅当**真的沿用了上一轮数据或整栏为空**时才提示——
常年 0 条贡献的源（如徐州博物馆偶发网络不通）挂掉不会吵。另有防呆：
抓取大幅降级且条数不足上次六成时，本轮不落盘，继续展示上一版。

## 数据源与口径

**演出**（格瓦拉生活网 + 大麦，两个独立平台，同一演出合并成一条、各给购票入口）：

- 格瓦拉（show.maoyan.com，美团系）：列表页前端 JSON 接口，单页 100 条可翻页，
  城市靠 `currentCity` cookie 切换；接口不通时回退 SSR 页面。
- 大麦（mtop.damai.cn，阿里系）：淘系 mtop 签名协议；话剧歌剧类目 `groupId=2333`，
  展览类目 `groupId=2370`。搜索类接口会被云出口 IP 风控，因此走 `project.classify`。
  昆山/常熟等县级市记录归到所属地级市，县名保留在场馆名里。

**展览**三路合并：

- 博物馆官网展讯（免费特展/临展）：南京博物院、上海博物馆、苏州博物馆、
  扬州中国大运河博物馆、徐州博物馆、中国丝绸博物馆 6 个馆，另有国家文物局
  「博物馆展讯速览」每月一期补录（兜住良渚博物院这类只发新闻稿的馆）。
  「博物馆」栏只在有展讯源的城市成表，其余城市本期不显示。常设展不收。
- 票务平台展览类目（格瓦拉 cat=9 / 大麦 2370）：只有卖票展；
  市集、研学、导览、亲子手作等非「展」活动按类目和标题词剔除。

判类口径：VR/XR、数字光影、沉浸式、IP/二次元、艺术展这类**内容型**展览一律归
「展览」栏，场馆只当地点；确实发生在博物馆/纪念馆里的特展临展才归「博物馆」栏。
两源同一特展撞车时以「博物馆」为准，避免一个售票入口把免费特展挤进展览栏。
合并键 `(展名核心, 城市, 起始日)`；稳定 id 用 md5（Python `hash()` 每进程随机，不可用）。

## 页面功能

- 五段切换：全部 / 音乐剧 / 话剧 / 博物馆 / 展览；「全部」按有效起始日排——
  已开演的（含长销展、驻演）归入「今天」组、按闭幕先后，未开演的按日期往后。
  博物馆/展览栏按闭幕日升序，快闭幕的在前。
- 时间窗（按闭幕日筛选）、城市（跟随栏目收窄）、关键词三个过滤。
- 天数标签按北京时间日历天计算：今天闭幕/明天闭幕/剩 N 天/演出中/已结束。
- 卡片含海报（源站 CDN 外链热图，本仓库不存图）、档期、场馆、票价与多源入口；
  免费展入口写作「预约」。新上架带 NEW，7 天内到期高亮。
- `calendar.ics` 可导入手机日历；演出与博物馆特展进日历，商业展览不进。
- 头部实时提示数据新鲜度，避免把「Actions 没跑」看成「今天没有新演出」。

## 本地运行

```bash
pip install -r requirements.txt          # 只有 requests

python3 crawler/scrape.py                # 抓四路信源并合并、落盘
python3 crawler/scrape.py --cities 上海,杭州
python3 crawler/scrape.py --no-damai     # 本轮只抓格瓦拉
python3 crawler/scrape.py --no-museum --no-expo   # 只要演出栏
python3 crawler/scrape.py --offline      # 只用缓存重建
python3 web/build.py                     # 内联快照 + dist/ + ics
python3 -m http.server 8000 -d web       # 本地预览
```

限流默认 1.2s/请求（环境变量 `TW_REQUEST_INTERVAL` 调整）。
一轮完整抓取（演出双源 + 6 馆 + 展览双源）约 100 秒。
`data/pages/` 为页面缓存（gitignore），CI 干净环境下不存在，属正常。

## 部署

### A. GitHub Actions + Pages（线上正在用，零成本）

推送本仓库到 GitHub → Settings → Pages 选 **GitHub Actions** 即可，
`scrape.yml` 会完成抓取、提交快照、部署。机器人提交的数据快照带
`[skip ci]` 且不触发路径过滤，不会自举循环。

### B. 自建服务器（备选，功能为早期版本）

```bash
docker build -f deploy/Dockerfile -t theatre-watch .
docker run -d --name theatre-watch -p 8080:8080 --restart unless-stopped theatre-watch
```

容器内 cron 固定北京时间 08:00/16:00 执行，无闸门与心跳机制；公网建议前置反代加 HTTPS。
